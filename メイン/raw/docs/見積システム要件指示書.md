# Claude Code 開発指示書:工務店向け見積もり作成Webシステム

## 1. 背景と目的

やまのすみか株式会社(注文住宅専門工務店、事務4名・現場6名)の見積業務を対象とする。現状の課題は、見積作成・実行予算作成・原価管理が分断されており、見積根拠の検証と予算進捗の把握に手作業を要すること。

本システムの目的は次の3点である。

1. 原価積上げ方式による見積作成の標準化
2. 過去実績(freeeデータ・過去請求書)に基づく見積単価の検証
3. 見積 → 実行予算 → 発生原価の一気通貫管理による予実進捗の自動可視化

本システムは ymsk-core プロジェクトの一部として構築する。基盤は Vercel + Supabase(PostgreSQL)、会計データソースは freee API(freee-mcp / Remote MCP 経由でも検証可能)。Phase 1 の SQL 設計資産があれば流用を優先すること。

## 2. 機能要件

### FR-1: 原価からの見積額算出

- 見積は階層構造とする(工事 > 大項目(仮設・基礎・木工事等) > 中項目 > 明細)
- 明細行は「数量 × 単価 = 原価」を基本とし、明細または項目単位で掛率(粗利率/掛け率)を設定して見積額(提出価格)を算出できること
- 掛率は「全体一括」「大項目別」「明細個別」の3段階で上書き可能とし、優先順位は 明細 > 大項目 > 全体
- 原価・見積額・粗利額・粗利率をリアルタイムに集計表示すること
- 単価マスタ(材料・労務・外注・経費の区分付き)を持ち、明細入力時にマスタ参照できること
- 消費税・端数処理ルール(切捨て/切上げ/四捨五入、円/千円単位)を事業所設定として持つこと

### FR-2: 過去実績データによる見積単価の検証

- freee の過去取引(deals)・請求書・仕訳データから、品目/取引先/メモタグ単位の実績単価を集計し、見積明細の単価と突合できること
- 明細入力時に「この品目の過去実績: 直近N件の単価レンジ・平均・最終取引日」をインライン表示すること
- 見積単価が実績レンジから乖離している場合(閾値は設定可能、初期値±15%)に警告表示すること
- 実績データは freee API から定期同期(または手動同期ボタン)で Supabase にキャッシュし、検証処理は自システム内で完結させること(freee API のレート制限対策)

### FR-3: 見積書と実行予算書の同時出力

- 見積確定時に、同一の明細データから「見積書(顧客提出用、掛率適用後)」と「実行予算書(社内用、原価ベース)」を同時に生成できること
- 両帳票は同一の見積バージョンに紐づき、明細の1対1対応を保証すること(見積と予算の項目ズレを構造的に排除)
- 出力形式: PDF(印刷用)+ Excel(編集用)。見積書は自社フォーマット(ロゴ・社判位置等はテンプレート化)
- 見積はバージョン管理すること(v1, v2...)。顧客との交渉過程で複数案を保持し、確定版を1つ指定できること

### FR-4: freeeメモタグ連携による原価自動取得と予実進捗管理

- 見積確定時に、案件に対応する freee メモタグ(例: `案件_田中様邸_2026`)を自動作成または既存タグと紐付けできること
  - freee API: `accounting` サービスの `/api/1/tags`(メモタグ作成・取得)、`/api/1/deals`(取引の `tag_ids` でフィルタ)
- 当該メモタグが付与された支出取引を定期同期し、実行予算の該当項目に自動仕訳(勘定科目・品目・取引先からのマッピングルール + 手動割当のフォールバック)すること
- 案件ダッシュボードで以下を表示すること:
  - 実行予算額 / 発生原価累計 / 残予算 / 消化率(項目別・全体)
  - 予算超過項目のアラート(超過・超過見込み)
  - 未割当原価(マッピングできなかった取引)の一覧と手動割当UI
- 同期方式: 初期は手動同期 + 日次バッチ。freee 側のデータが正、自システムは読み取り専用キャッシュとする(二重管理を避ける)

### FR-5: 複数人での同時作業

- 事務スタッフ4名の同時利用を前提とする
- 認証: Supabase Auth(メール + パスワード、将来的にGoogle SSO)
- 権限ロール: 管理者(マスタ・掛率・freee連携設定) / 一般(見積作成・閲覧)の2段階から開始
- 同一見積の同時編集は「明細行単位の楽観ロック」とし、競合時は後勝ちではなく警告 + マージUIを表示すること
- 変更履歴(誰が・いつ・どの明細を変更したか)を監査ログとして保持すること

### FR-6: キーボード完結の入力操作

- 見積明細の入力・編集はマウスなしで完結できること。Excel同等の操作感を目標とする
- 必須キーバインド:
  - `Tab` / `Shift+Tab`: セル間移動、`Enter`: 下のセルへ、`Esc`: 編集キャンセル
  - `Ctrl+D`: 上の行を複製、`Ctrl+Insert` または `Alt+N`: 行追加、`Ctrl+Delete`: 行削除
  - `Ctrl+S`: 保存、`Ctrl+Z` / `Ctrl+Shift+Z`: Undo/Redo
  - `/` または `Ctrl+K`: 単価マスタのインクリメンタル検索(検索結果も矢印キー + Enter で選択)
- 数量・単価セルは IME 制御(自動的に半角数値モード)すること
- グリッド実装は既製ライブラリ(例: Glide Data Grid, AG Grid Community 等)の採用を検討し、自作は最終手段とすること

## 3. 非機能要件

- スタック: Next.js (App Router) + TypeScript / Supabase (PostgreSQL, Auth, RLS) / Vercel。ymsk-core の既存規約に従う
- freee 連携: サーバーサイドで freee API を直接叩く(OAuth2)。開発・検証フェーズでは freee-mcp を使ったデータ確認を併用可
- RLS(Row Level Security)を全テーブルに適用すること
- レスポンス: 明細100行規模の見積で入力遅延を体感させないこと(集計はクライアント側計算 + 保存時サーバー検証)
- バックアップ: Supabase の PITR に依存しつつ、確定見積は帳票PDFをストレージに不変保存

## 4. データモデルの骨子(Phase 1 SQL設計と整合させること)

- `projects`(案件) — freee メモタグID を保持
- `estimates`(見積ヘッダ、バージョン管理)/ `estimate_items`(階層明細、原価・掛率・見積額)
- `budgets`(実行予算ヘッダ)/ `budget_items`(見積明細と1対1)
- `cost_actuals`(freee 取引キャッシュ、tag_id・deal_id・勘定科目・金額・日付)
- `cost_allocations`(発生原価 → 予算項目の割当、自動/手動フラグ)
- `price_master`(単価マスタ)/ `price_history`(freee実績から集計した実績単価)
- `users` / `audit_logs`

## 5. 開発フェーズ提案

| Phase | 範囲 | 完了条件 |
|-------|------|---------|
| 1 | FR-1 + FR-6(見積作成コア + キーボードグリッド) | 明細入力→掛率→見積額算出がキーボードのみで完結 |
| 2 | FR-3 + FR-5(帳票出力 + マルチユーザー) | 見積書/実行予算書PDFの同時出力、4名同時利用 |
| 3 | FR-4(freeeメモタグ連携・予実ダッシュボード) | タグ付き取引の自動取込と消化率表示 |
| 4 | FR-2(実績単価検証) | 明細入力時の実績レンジ表示と乖離警告 |

FR-2 を最終フェーズとする理由: 実績データの蓄積・品目マッピングの精度が FR-4 の運用実績に依存するため。

## 6. 受入基準(抜粋)

1. 明細50行の見積を、マウス不使用・10分以内で新規作成できる
2. 見積書と実行予算書のPDFで、全項目の対応関係と合計金額の整合が取れている
3. freee でメモタグ付き支出取引を登録後、同期実行で該当案件の消化率に反映される
4. 2名が同一見積の異なる明細を同時編集しても、双方の変更が失われない
5. 単価がマスタ実績レンジ±15%を超えた場合に警告が表示される
