# ymsk-core セッション 2026-07-05

ymsk-core（現 [[Yamasemi]]）専用プロジェクトの単発大型セッション（2026-07-05〜06、317ターン・約12時間）。ユーザーがほぼ全編スマホから遠隔指示するという制約下で、見積システム第1段階を大きく前進させた。

## 何が起きたか

- 前セッションの引き継ぎ処理（残置テストデータ削除、E2E を DB/RPC 直接呼び出しで代替検証: 階層採番 A / A.a / A.b.1・金額集計・永続化）
- スマホからの動作確認要望を受けて Vercel CLI をデバイス認証で接続。その過程で「Vercel ビルドが型エラーで失敗し続けていた」「Deployment Protection がスマホを遮っていた」の2問題を発見
- 実行予算システムの設計→ユーザー承認→実装（確定ボタン・新バージョン複製・予実ダッシュボード）
- 単価マスタ登録（Ctrl+K検索）、案件紐付けUI、見積書PDF（工種別内訳付き）、FR-5（権限ロール・監査ログ・楽観ロック）、GLOOBE向けIFCプロトタイプパーサー

## 主要な設計判断（理由つき）

- **budget_items は estimate_nodes のスナップショット（値コピー）**: save_estimate_nodes RPC が全削除→全再挿入方式のため、FKで繋ぐと確定後の保存でFK違反になる
- **実行予算は原価ベース**で管理し見積額（提出価格）は参考値（承認済み）。有効予算はプロジェクト単位1件のみ・再確定時は旧予算 superseded 化
- **確定済み見積は編集不可、修正は「新バージョン複製」一本化**
- **FR-5 は3点セット**（監査ログ・権限ロール・行単位の楽観ロック=警告+マージUI）と再定義
- **push 前 `npm run build` 必須化**: lint/vitest では next build 特有の型エラーを検出できなかった反省から
- **Deployment Protection は現状維持**: 本人が一度「無効化せよ」と指示したが Claude がセキュリティ設定変更として代行を拒否・手順のみ提示し、最終的に本人が「やめとく」と判断
- **DDL はユーザーの手作業に限定**: Claude の鍵は PostgREST 経由のデータ操作のみという権限分離を維持
- PDF は WOFF2→TTF 切替でファイルサイズ 7MB→250KB（「エラーなく動いた」と「正しく動いた」は別、の実例）
- freee API の前提知識をコードより先に公式リファレンスで検証（Web検索由来の誤情報を訂正）

## 業務要件として読み取れたもの

- 見積は 工種→中分類→明細 の3階層・キーボード主体入力（Excel 的高速入力の志向）→ [[原価管理パイプライン]]
- 掛率（原価→提出価格の倍率）は経営情報として一般ロールから隠す
- 少人数でも同一見積の同時編集は起きる前提（後勝ちでなく行単位競合検出）
- BIM 連携: 実IFC（ホームズ君構造EX・IFC2X3）から材積・耐力壁面積・樹種・金物610件が取得可能と確認。IFCBEAM/IFCMEMBER の分裂、型エンティティ側プロパティ等の落とし穴も記録
- freee 連携タスクは実行予算の存在が前提 → 「freee より先に実行予算設計」の順序が確定
