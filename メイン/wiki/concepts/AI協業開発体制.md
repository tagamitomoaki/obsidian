# AI協業開発体制

田上さんが1日約3時間で [[Yamasemi]] と [[swing-tradeシステム]] を回すための分業構造。出発点は 2026-07-04 の問題の再定義: **「原価掌握が後手」ではなく「計画の生産量に対して実行者が本人一人しかいない」** → 本人「着工」で体制が始動。

## 分業（関所の設計）

| 役 | 担当 |
|---|---|
| 田上さん（施主役） | 承認・main マージ判断・migration の SQL Editor 適用・シークレット登録・admin 付与・実機確認 |
| Claude Code | 実装主担当・計画・検証・git 操作・ドキュメント保守 |
| [[Codex]] | 独立レビュー/敵対的監査・仕様明確なタスクの並行実装（原則: 書いた本人だけがレビューしない） |
| [[西永さん]] | 実機テスト・業務観点レビュー→自分の Claude Code での開発参加へ発展 |

「取り消しにくい操作」だけを人間の関所に残し、**「未適用でも壊れないコード + 冪等 SQL」の2つの約束**で DB 適用とマージの順序が入れ替わっても事故らないようにするのが核。

## 運用の道具立て

- **handoff 運用**: docs/handoff.md（全体像の正本）+ session-handoff-YYYYMMDD.md（直近差分）。「handoff」の一語で任意のセッション・端末から再開。swing-trade も同型（session-handoff.md 起点）
- AGENTS.md = エージェント共通ルールの正本（CLAUDE.md は @参照）、known-issues-log.md = 優先度付き課題台帳
- git worktree でセッション・エージェントを分離（共有ワーキングコピーはコミット直前のブランチ確認必須）
- 多エージェント自己レビュー（8観点×2回+ユーザビリティ5体+スケーラビリティ3体で実バグ12件超を捕捉した実績）、銘柄調査の7〜12体並列 Web 照会
- Sonnet サブエージェントへの量産委任は**全数検証とセット**（ブログ誤変換65/100本の事故: モデルに長文を打ち直させると系統的誤変換が起きる → 機械送信は REST スクリプトで）

## ツールの位置づけ

- ローカルLLM（Ollama/qwen3.6）: 品質勝負は価値ゼロ。機密データの下処理・大量機械処理・カスケードふるい分け・ダミーデータ生成に価値
- Grok Build: 調査の上、導入見送り（「Codex が痛くなったら再検討」）
- /advisor スキル: 技術+工務店業務の両面顧問（推奨→根拠→反対視点→やらないこと→次の一手の形式）

## 方向性: AI-native へ

Boris Cherny「Steps of AI Adoption」の Step 4（人間がエージェントを起動する側から、動き続けるシステムを設計して例外だけ見る側へ）を目標に、現在地は Step 2〜3。道筋: ①自己検証ループの信頼性向上 → ②定常業務のルーチン化とスケジュール実行 → ③Yamasemi への Agent SDK 組み込み。ガードレール（お金・本番 migration・対外公開は人間承認）の明文化が前提。

## セキュリティ面の論点

- 開発機分離（Mac 購入案）は保留: サンドボックス・ブラウザプロファイル分離・クレデンシャル最小化を現行機で先に試す条件付き判断（2026-07-23）
- 同期する Vault/リポジトリに秘密情報を書かない、リポジトリを Google Drive に置かない、`.env` 運用の徹底 → [[開発原則]]
