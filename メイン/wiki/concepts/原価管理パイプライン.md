# 原価管理パイプライン

[[やまのすみか]]の中核業務課題「原価掌握の後手」への回答。真因は機能不足ではなく **[[freee]]→サクミルへの手転記** であり、[[Yamasemi]] 第1段階はこの転記の廃止そのもの。

## 流れ

```
階層見積（工種→中分類→明細）
  → 確定（原価妥当性チェック → 承認 → 計上漏れチェック → confirm_estimate）
  → 実行予算（budgets / budget_items = 見積のスナップショット）
  → freee 実績同期（メモタグ=現場名で案件紐付け）
  → 予実対比（品目別の発生原価・消化率・予算残・予算外品目の検知）
  → ¥/㎡ 実績参考値として次の見積へ還流
```

## 確定している設計判断

- **実行予算は「原価」ベース**。見積額（提出価格）は参考値。契約金額との差分から粗利・粗利率を算出
- **budget_items は見積のスナップショット（値コピー）で、生きた FK で繋がない**（保存 RPC が全削除→全再挿入方式のため）。確定済み見積は編集不可、修正は「新バージョン複製」一本化。有効予算は案件単位1件のみ
- **掛率（原価→提出価格の倍率）は経営情報**として一般ロールから隠す
- **人の承認より機械検証を優先**（本人の言: 「人間は当てにならない」）: 工種別 ¥/㎡ を他案件中央値と比較する異常値検出（乖離±40%超で要確認、過去にズレた5工種は重点±25%）、計上漏れチェック（スキップ理由必須）、予算外品目の検知行
- **¥/㎡ 参考値は単価を自動上書きしない**（人間承認フロー）
- 発生原価の工種別配賦（cost_allocations）は**手動**（自動割当は誤配賦リスクで見送り）
- 見積の標準タクソノミー: 「明細が細かすぎる」の正体は中分類の欠落 → 明細は削らず21工種+標準中分類のテンプレートで新規見積を生成。明細行テンプレートは実データ455行→キュレーションで119行

## BIM からの概算見積（前段の自動化）

案件に基準面積6種（延床・基礎・外壁・屋根・天井・内壁）を持たせ、㎡建て明細の数量を自動プリフィル。

- GLOOBE 意匠 IFC: 仕上げ面積・建具（窓・ドア型番→見積の建具工種へ自動展開）・屋根が取得可 → 6種中5種が自動化（外壁のみ手転記）
- ホームズ君構造EX の IFC: 木拾い向き（断面・材積・樹種・耐力壁面積・金物）
- 実装は JS 簡易パーサー（本番級は IfcOpenShell+Cloud Run 構想だが、外部サービス追加の保守コストを理由に見送り中）
- IFC の落とし穴（実測）: 梁系が IFCBEAM と IFCMEMBER に分裂（棟木・母屋は後者）、独自プロパティは型エンティティ側に付く、単位不統一

## 残っている作業

- freee 原価実績の本実装（cost_actuals / cost_allocations テーブル）と過去4案件の見積↔実原価突合
- 実行予算書 PDF は実装済み、確定時 PDF の不変保存は契約のみ（見積は未設計）
